Leon Sandbox Middleware

Isolated execution environments for AI agents. Provider-agnostic abstraction layer.

Architecture Overview

The sandbox middleware provides a clean separation between Leon's agent runtime and the underlying execution environment. This allows swapping providers (cloud containers, local Docker, etc.) without changing agent code.

+------------------+ +-------------------+ +------------------+ | Leon Agent | --> | SandboxMiddleware | --> | SandboxManager | | | | | | | | - Receives task | | - Creates tools | | - thread_id map | | - Calls tools | | - Binds thread_id | | - SQLite persist | +------------------+ +-------------------+ +------------------+ | v +-------------------+ +------------------+ | SandboxProvider | <-- | Provider Factory | | (Interface) | | | +-------------------+ +------------------+ ^ | +-----------------------+-----------------------+ | | | +-----------------+ +-----------------+ +-----------------+ | AgentBayProvider| | E2BProvider | | DockerProvider | | (implemented) | | (future) | | (future) | +-----------------+ +-----------------+ +-----------------+

SandboxMiddleware
middleware/sandbox/middleware.py
  • Factory pattern for tool creation

  • Tools: read_file, write_file, edit_file

  • Alibaba Cloud AgentBay SDK

Data Flow

User Request | v +------------------+ | Leon Agent | +------------------+ | v +------------------+ | SandboxMiddleware| <-- Check thread_id (ContextVar) +------------------+ | v +------------------+ | SandboxManager | <-- get_or_create_session(thread_id) +------------------+ | +---> [Session exists?] | | | Yes | No | | | | | v | v | [Paused?] | Provider.create_session() | | | | | v | | | Resume | | | | | | +----+-------+-----+ | v +------------------+ | Execute Tool | <-- read_file, run_command, etc. +------------------+ | v +------------------+ | Return Result | +------------------+

Session Lifecycle

Thread Start | v (lazy - on first tool call) +------------------+ | Create Session | +------------------+ | v +------------------+ | Session RUNNING | <----+ +------------------+ | | | v | [Thread Switch / Exit] | | | v | +------------------+ | | Pause Session | | | (if supported) | | +------------------+ | | | v | [Resume Thread] ----------+ | v [Explicit Delete / TTL] | v +------------------+ | Destroy Session | +------------------+

Configuration

# In profile.yaml
sandbox:
  enabled: true
  provider: agentbay
  replace_local_tools: true  # Disable local fs/command tools
  context_id: my-context     # Optional persistent storage

  agentbay:
    api_key: null  # Use AGENTBAY_API_KEY env var
    context_path: /root

Key Options

replace_local_tools: true disables Leon's local FileSystemMiddleware and CommandMiddleware, forcing all operations through the sandbox. This is the recommended setting for untrusted workloads.

context_id enables persistent storage across sessions. Files written to context_path survive session destruction.

Implementation Status

What Works

  • Provider abstraction with AgentBay implementation
  • Lazy session creation bound to thread_id
  • Standard tool names (read_file, run_command, etc.)
  • Session manager TUI
  • Sandbox-specific system prompt injection
  • Metrics and screenshot capture

Known Limitations

  • Pause/Resume requires higher AgentBay tier
  • Context persistence not fully tested
  • No auto-pause on thread switch yet
  • E2B and Docker providers not implemented

Code Example

Adding a New Provider

# middleware/sandbox/providers/my_provider.py
from ..provider import SandboxProvider, SessionInfo

class MyProvider(SandboxProvider):
    async def create_session(self, thread_id: str) -> SessionInfo:
        # Create container/VM/etc
        session_id = await self._create_environment()
        return SessionInfo(
            session_id=session_id,
            thread_id=thread_id,
            status="running"
        )

    async def execute(self, session_id: str, command: str) -> str:
        # Run command in sandbox
        return await self._run_in_container(session_id, command)

    async def read_file(self, session_id: str, path: str) -> str:
        # Read file from sandbox filesystem
        return await self._read_from_container(session_id, path)

    # ... implement remaining interface methods

Using ContextVar for Thread Binding

# The middleware uses ContextVar to track thread_id across async calls
from contextvars import ContextVar

thread_id_var: ContextVar[str] = ContextVar('thread_id')

# Set when entering a thread context
thread_id_var.set(current_thread_id)

# Tools read it without explicit parameter
def read_file(path: str) -> str:
    thread_id = thread_id_var.get()
    session = manager.get_or_create_session(thread_id)
    return provider.read_file(session.session_id, path)
